直接 `main` ブランチにコミットしないような運用をしている場合(組織内などで複数人が関わってソフトウェア開発しているような状況で一般的だと思います)、敢えて `main` ブランチをローカルに作成する必要はないのでは、という話です。

`git clone <URI>` コマンドを実行すると、`main` ブランチがチェックアウトされた状態でワーキングディレクトリーが作成されるので、それをそのままにしている人が多いと思います。

しかしよく考えてみてください。ローカルで `main` ブランチに対して操作することなんて無いのに、作成する必要は無いでしょう。

なまじ存在しているせいで、最新状態と同期取らなきゃ、と考えいちいち

```bash
git checkout main
git pull
```

なんて定期的にやってる人もいるのではないでしょうか。
わざわざ使わないブランチのために古いコードをチェックアウトして最新化する、みたいな往復って無駄の極みですよね。

また実害として(今現在は当時より賢くなっているので再現するかわからないですが)、AIが本来は最新の`main`ブランチのコードを確認したいときに、ローカルの`main`ブランチのコードを見に行ってしまう、という問題が時々ありました。
この問題のせいで、余計にローカル`main`を定期的に最新化しなきゃ、と考えてしまっている人ももしかしたらいるんじゃないでしょうか。

考え方を変えましょう。ローカルに`main`は不要なのだと。
最新の`main`の状態が欲しいならリモートトラッキングブランチ `origin/main` をチェックアウトすればよいのです。
わざわざ古いコードをチェックアウトする必要はありません。

```bash
git fetch
git checkout origin/main
```

なお、既に存在している`main`ブランチを削除するには:

```bash
git branch -D main
```

`main`ブランチが元から存在していないと、`main`ブランチがある前提で動くプログラムだったり`main`ブランチを作ろうとしてくるプログラムだったり、お行儀の悪いものが炙り出されるのも良いです。
